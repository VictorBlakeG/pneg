# Accessibility Review — pn-junc-sim (Simple PN Junction Simulator)
**Date:** 2026-03-23
**File(s):** pn-junction-simulator.html
**Standard:** WCAG 2.1 Level AA

## What Was Checked
1. Color contrast (text, UI components)
2. Color as sole indicator
3. Font sizes (minimum 12px, use of em/rem vs px)
4. Text resizing / 200% zoom
5. Form labels (associated labels for inputs/selects)
6. Focus indicators (visible focus styles)
7. Keyboard navigation (tab access to all controls)
8. ARIA / semantic HTML (headings, landmarks, roles)
9. Images of text
10. SVG/Canvas accessibility (text alternatives for visualizations)

## Findings

### 1. Color Contrast

**Light mode (default):**
- `h1` text `#1f2937` on body `#f9fafb` -- approx 14.5:1. PASS.
- Label text `#374151` on white panel `#ffffff` -- approx 8.5:1. PASS.
- `.chart-info` text `#6b7280` on white -- approx 5.0:1. PASS (normal text >= 4.5:1).
- `.calc-step .label` italic text `#6b7280` on `#f8fafc` -- approx 4.8:1. Borderline PASS.
- `.calc-step .result` green text `#059669` on `#f8fafc` -- approx 4.1:1. **FAIL** for normal-size text (requires 4.5:1).
- `.calc-step .formula` blue text `#1e40af` on `#f8fafc` -- approx 7.5:1. PASS.

**Dark mode:**
- Body text `#c8d8f0` on `#050a14` -- approx 11:1. PASS.
- Info labels `#7ab8f8` on `#080f1e` -- approx 7.5:1. PASS.
- Result text `#00ff88` on `#0a1428` -- approx 10:1. PASS.
- Select/input border `#1a3a6a` on dark bg `#0a1428` -- approx 2.5:1. **FAIL** for UI component contrast (requires 3:1).

### 2. Color as Sole Indicator

- Chart lines use color to distinguish datasets (Ec=blue, Ev=red, Ei=purple, Ef=green). However, the help panel provides a text legend with labels, and Chart.js renders an interactive legend. **Partial pass** -- the legend mitigates the issue, but line patterns (dash/dot) would improve discriminability.
- No other controls rely on color alone; checkboxes and radio buttons have text labels.

### 3. Font Sizes

- Labels use `font-size: 0.875rem` (14px at default root). PASS.
- Info grid uses `0.875rem`. PASS.
- Theme toggle button uses `font-size: 12px` (hardcoded px). Borderline PASS on size, but **uses px instead of rem**, preventing user font-size scaling.
- All other text uses rem units. Generally good.

### 4. Text Resizing / 200% Zoom

- Layout uses `grid-template-columns: repeat(auto-fit, minmax(250px, 1fr))` -- responsive and should reflow.
- Media query at 768px collapses grids to single column. PASS.
- `.chart-wrapper` has a fixed `height: 500px` (inline style). At 200% zoom the chart container will clip or require scrolling. **Concern** -- not a hard fail since charts are inherently fixed-size, but content may be obscured.
- No `overflow: hidden` on major containers. Generally acceptable.

### 5. Form Labels

- `<label for="material">` correctly associated with `<select id="material">`. PASS.
- `<label for="temperature">` correctly associated with range input. PASS.
- `<label for="nDopant">`, `<label for="pDopant">`, `<label for="nConc">`, `<label for="pConc">`, `<label for="forwardBias">` -- all correctly associated. PASS.
- `<input type="checkbox" id="showQuasiFermi">` has `<label for="showQuasiFermi">`. PASS.
- `<input type="checkbox" id="showEi">` has `<label for="showEi">`. PASS.
- `<input type="checkbox" id="showCalculations">` has `<label for="showCalculations">`. PASS.
- Radio buttons (`tempPreset`, `qflMode`) are wrapped in `<label>` elements. PASS.
- **Theme toggle button** (`#theme-toggle`) has visible text. PASS.

### 6. Focus Indicators

- No custom `:focus` or `:focus-visible` styles are defined in the CSS.
- Browser default focus outlines will apply for `<select>`, `<input>`, `<button>` elements. This relies entirely on browser defaults, which may be insufficient (e.g., Chrome's thin blue outline can be hard to see on light backgrounds).
- **FAIL** -- No explicit focus styles defined. Custom focus indicators should be added for reliable visibility.

### 7. Keyboard Navigation

- All form controls (`<select>`, `<input type="range">`, `<input type="checkbox">`, `<input type="radio">`, `<button>`) are natively keyboard-focusable. PASS.
- No `tabindex="-1"` found that would remove elements from tab order. PASS.
- No keyboard traps detected. PASS.
- Chart.js canvas elements are not keyboard-interactive but are display-only. Acceptable.

### 8. ARIA / Semantic HTML

- Uses `<h1>` for page title. PASS.
- Uses `<h3>` for section titles within info panels (skipping `<h2>`). **FAIL** -- heading hierarchy skips from h1 to h3.
- Uses `<h4>` for calculation sub-sections. PASS (within h3 context).
- No `<main>`, `<nav>`, `<section>`, or `<article>` landmark elements used. The entire page is inside a `<div class="container">`. **FAIL** -- no landmark regions.
- No ARIA roles, `aria-label`, or `aria-describedby` attributes present anywhere. **FAIL**.
- Range sliders display their current value in a `<span>` inside the associated `<label>`, which is good for visual users but not programmatically linked via `aria-valuenow` / `aria-valuetext`.
- `lang="en"` is set on `<html>`. PASS.

### 9. Images of Text

- No `<img>` elements in the document. PASS.
- Text content is rendered as actual text (HTML/CSS). PASS.
- Scientific notation and subscripts use `<sub>` and Unicode characters. PASS.

### 10. SVG/Canvas Accessibility

- Three `<canvas>` elements (`#bandChart`, `#potentialChart`, `#efieldChart`) are used for Chart.js visualizations.
- None of the canvas elements have fallback text content, `aria-label`, or `role="img"`.
- **FAIL** -- Canvas charts have no text alternative for screen readers.
- No `<figcaption>` or descriptive text programmatically linked to the charts.
- The `#chartInfo` and `#potentialChartInfo` divs provide some descriptive text but are not linked to the canvases via ARIA.

## Recommended Fixes

A. **Add visible focus indicators.** Define `:focus-visible` styles for all interactive elements (inputs, selects, buttons) with a minimum 2px outline and 3:1 contrast against adjacent colors. Example: `*:focus-visible { outline: 2px solid #2563eb; outline-offset: 2px; }`

B. **Fix green result text contrast.** Change `.calc-step .result` color from `#059669` to `#047857` (darker green) to achieve at least 4.5:1 on the `#f8fafc` background.

C. **Fix dark-mode input border contrast.** Change dark-mode select/input `border-color` from `#1a3a6a` to `#2a5aaa` or brighter to meet 3:1 against the `#0a1428` background.

D. **Fix heading hierarchy.** Change info-panel headings from `<h3>` to `<h2>`, or add an `<h2>` section wrapper above them. Sub-sections in calculations can then use `<h3>`.

E. **Add landmark regions.** Wrap controls in `<form role="search">` or `<section aria-label="Controls">`. Wrap charts in `<main>`. Wrap help text in `<aside>`. Add `role="region"` with `aria-label` to calculation sections.

F. **Add canvas text alternatives.** Add `role="img"` and `aria-label="Energy Band Diagram showing [description]"` to each `<canvas>`. Alternatively, link the chart-info divs via `aria-describedby`. Example: `<canvas id="bandChart" role="img" aria-label="Energy band diagram for the P-N junction"></canvas>`

G. **Convert px font sizes to rem.** Change the theme toggle button `font-size: 12px` to `font-size: 0.75rem`.

H. **Add distinguishing line patterns to charts.** Configure Chart.js datasets with `borderDash` arrays so chart lines are distinguishable without color (e.g., solid, dashed, dotted).

I. **Add `aria-valuenow` and `aria-valuetext` to range sliders.** Update JavaScript to set these ARIA attributes on range inputs whenever their values change, so screen readers announce the current value with units (e.g., "Temperature: 300 K").

J. **Consider making chart height responsive.** Replace fixed `height: 500px` with a min-height and allow flex growth, or use `max-height` with `overflow: auto` to handle 200% zoom gracefully.
